# GitLab Vars Mode — `docs/gitlab-variables.md` 자동 생성

## 목적

GitLab → Settings → CI/CD → Variables에 **등록해야 할 모든 키**를 prefix 규칙대로 확장해 체크리스트 markdown으로 출력. 팀원이 이 파일 열어 놓고 GitLab 화면과 대조하며 하나씩 등록.

## 입력 소스

모두 `$REPO`(=`git rev-parse --show-toplevel`) 기준.

### 1. 코드가 실제로 참조하는 키 (check-mode.md와 동일 grep)

- backend: `app/backend/src/**/*.{yml,kt}` 의 `${KEY}`, `@Value("\${KEY}")`
- frontend: `app/frontend/src/**/*.{ts,tsx}` 의 `import.meta.env.VITE_KEY`
- ai: `app/ai/**/*.py` 의 `os.getenv("KEY")` / `os.environ["KEY"]`

### 2. `infra/env/README.md` 테이블의 키

prefix 있는 형식 그대로 추출:

```bash
grep -oE '`ENV_(BASE|DEV|MASTER)(_(BACKEND|FRONTEND|AI|INFRA))?_[A-Z][A-Z0-9_]+`' \
  "$REPO/infra/env/README.md" \
  | sed 's/`//g' | sort -u
```

### 3. `.gitlab-ci.yml`의 시스템 변수

`DISCORD_WEBHOOK_URL` 등 prefix 없이 직접 쓰이는 키:

```bash
grep -oE '\$[A-Z][A-Z0-9_]+|\$\{[A-Z][A-Z0-9_]+' "$REPO/.gitlab-ci.yml" \
  | sed -E 's/^\$\{?//' \
  | grep -vE '^CI_' \
  | sort -u
```

## 분류 규칙

코드 참조 키 `<KEY>`가 있으면 다음을 생성:

| 원 키 | 서비스 판정 | 생성되는 GitLab Variable |
|---|---|---|
| backend 코드 참조 | backend | `ENV_DEV_BACKEND_<KEY>`, `ENV_MASTER_BACKEND_<KEY>` |
| frontend 코드 참조 (VITE_*) | frontend | `ENV_DEV_FRONTEND_<KEY>`, `ENV_MASTER_FRONTEND_<KEY>` |
| ai 코드 참조 | ai | `ENV_DEV_AI_<KEY>`, `ENV_MASTER_AI_<KEY>` |
| infra 표준 (whitelist의 Docker 이미지 표준) | infra | `ENV_DEV_INFRA_<KEY>`, `ENV_MASTER_INFRA_<KEY>` |
| 시스템 (DISCORD_WEBHOOK_URL 등) | system | 그대로 |

예외:
- whitelist.md의 **Compose/CI 전용** 키(`ENV_DIR`, `REGISTRY`, `APP_IMAGE_TAG` 등)는 GitLab Variables 등록 대상 아님 → 출력 제외
- Spring 표준 indirect 키(`SPRING_DATASOURCE_*`)는 주로 `DB_*` 형태로 등록 → whitelist 참고

## Masked / Protected 판정

정규식 매칭:

```python
is_masked = re.search(r'_(PASSWORD|TOKEN|KEY|SECRET|WEBHOOK|DSN)(_|$)', key)
is_protected = target == 'MASTER' and is_masked
```

## 체크박스 보존

기존 `docs/gitlab-variables.md`가 있으면:

1. 파일 파싱해서 `- [x] \`<VARIABLE_NAME>\`` 형태의 체크된 키 목록 추출
2. 새로 생성할 때 해당 키가 여전히 존재하면 `- [x]`로 유지
3. 키가 사라졌으면 제거 (등록 상태와 무관하게 의미 없는 체크)
4. 새 키는 `- [ ]`로 시작

## 출력 파일 구조

`docs/gitlab-variables.md`:

```markdown
# GitLab CI/CD Variables 등록 체크리스트

> ⚠️ AUTO-GENERATED by env-sync (gitlab-vars mode). 직접 수정 금지.
> 마지막 생성: <ISO8601 timestamp>

등록 위치: **Settings → CI/CD → Variables → Add variable**

체크박스는 등록 완료한 팀원이 체크 후 commit해 팀 진행 상황 공유.

---

## 시스템 변수 (prefix 없음)

- [ ] `DISCORD_WEBHOOK_URL` — **Variable** · **Masked ✅** — Discord 채널 웹후크

## ENV_BASE_* (dev/master 공통)

(있으면 여기)

## ENV_DEV_*

### Backend
- [ ] `ENV_DEV_BACKEND_<KEY>` — Variable · Masked? · 설명(있으면)
...

### Frontend
...

### AI
...

### Infra
...

## ENV_MASTER_*

동일 구조, Protected ✅ 표시 추가.

### Backend
- [ ] `ENV_MASTER_BACKEND_<KEY>` — Variable · Masked ✅ · Protected ✅
...

---

## 자동 분류 규칙

- `_(PASSWORD|TOKEN|KEY|SECRET|WEBHOOK|DSN)(_|$)` 매칭 → Masked ✅
- `ENV_MASTER_*` + Masked → Protected ✅
- 그 외 → plain Variable

## 업데이트

`/env-sync gitlab-vars` 실행으로 재생성. 체크박스 상태는 가능한 한 보존됨.
```

## 실행 흐름

1. **기존 파일 파싱** (있으면) → 체크된 키 셋 만들기
2. **키 수집**:
   - 코드 grep 3종
   - README 테이블 파싱
   - `.gitlab-ci.yml` 시스템 변수
3. **화이트리스트 필터**: whitelist.md의 Compose/CI 전용 키 제외
4. **prefix 확장**: 서비스 판정 결과에 따라 `ENV_<TARGET>_<SVC>_<KEY>` 생성 (dev/master 각각)
5. **Masked/Protected 태그**
6. **설명 채우기 (best-effort)**:
   - `infra/env/README.md` 테이블의 같은 키의 설명 열 복사
   - 없으면 빈칸
7. **체크박스 적용**: 기존 체크된 키는 `- [x]`, 나머지는 `- [ ]`
8. **파일 출력**: `docs/gitlab-variables.md` 덮어쓰기

## 주의사항

- **GitLab API 호출 없음** — 순수 로컬 생성. 현재 GitLab 등록 상태와 파일 체크박스는 수동으로 동기화 (팀 commit 규칙으로).
- **체크박스가 무단 수정되면 드리프트 발생 가능** — 팀 규칙: 재생성 후 체크박스는 "**실제 등록 완료한 사람이 commit**"으로 유지.
- **ENV_BASE_* 판정은 수동 영역** — 스킬은 기본적으로 환경별로 쪼개고 `ENV_BASE_*`는 빈 섹션으로 둠. 공통값이 있으면 사용자가 README를 먼저 수정한 뒤 재생성.
